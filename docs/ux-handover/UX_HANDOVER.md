## Screen annotations

### S00 — Resume application

- **Purpose:** Let an applicant return to an incomplete application without losing progress.
- **Who sees it:** Any applicant with a saved, unsubmitted application.
- **Entry condition:** Saved application exists, not submitted; applicant opens the onboarding entry point.
- **Required inputs:** None (choice only)
- **Primary action:** Continue application
- **Next:** The last active step (e.g. S08 Business details).
- **Alternative paths:** Start a new application → S01 (previous draft discarded in this demo).
- **Backend behaviour:** Demo: browser storage. Production: server-side draft keyed by application ID.; Production should re-authenticate with OTP before showing saved data (assumption D-15).
- **Business rules:** Submitted applications cannot be resumed or resubmitted.
- **UX/UI notes:** Show last-saved time and the step name, not internal status.; Never show unmasked identity data on this screen. — see G-UX.
- **States:** [Saved application found](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S00--resume)

### S01 — Start application (shared entry)

- **Purpose:** Capture applicant type, identification, annual revenue and mobile on one page.
- **Who sees it:** Every new applicant (Registered Business and Freelancer).
- **Entry condition:** Applicant opens onboarding, or returns via "Edit details" / "Edit mobile number".
- **Required inputs:** Applicant type (Registered Business / Freelancer); CR number (business) or National ID (freelancer) — field switches with type; Annual revenue (3 bands); Mobile number (+966 default)
- **Primary action:** Next
- **Next:** S02 OTP verification (after backend duplicate checks).
- **Alternative paths:** Identity already registered → S01-X Existing account.; Mobile already verified in this application and unchanged → revenue routing (OTP skipped).
- **Backend behaviour:** Check 1: identity (CR / National ID) duplicate — runs first.; Check 2: mobile linkage — only if identity is new; informational, never blocks.; Changing type resets incompatible data; changing ID resets identity-dependent verifications; changing mobile resets OTP.
- **Business rules:** All fields mandatory.; Freelancing certificate number is NOT requested here.; Exactly SAR 100,000 falls in the middle band (provisional D-01).; Format rules are configurable structural checks, not government validation.
- **UX/UI notes:** Inline errors per field plus an error summary on submit.; After Nafath has started, type and ID are read-only. — see G-UX.
- **States:** [Empty form](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S01--empty) · [Registered Business — completed](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S01--filled-cr) · [Freelancer — National ID field](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S01--filled-freelancer) · [Validation — required fields missing](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S01--errors-empty) · [Validation — invalid identification and mobile format](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S01--errors-format) · [Loading — backend duplicate checks](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S01--checking)

### S01-X — Existing account found

- **Purpose:** Stop a duplicate application for an identity that is already registered.
- **Who sees it:** Applicants whose CR or National ID already exists.
- **Entry condition:** Duplicate check 1 (identity) returned "already registered".
- **Required inputs:** None
- **Primary action:** Sign in to your account (outside prototype scope)
- **Next:** Existing-account sign-in (not designed here).
- **Alternative paths:** Contact support.; Edit details → S01.; Freelancer: "Add another certificate" → S01-F (future flow).
- **Backend behaviour:** Mobile check is skipped when identity already exists.; No new application record is created.
- **Business rules:** Same CR / National ID can never be registered twice.; Mobile reuse alone is never a reason to show this screen.
- **UX/UI notes:** Message must not reveal account details to an unverified visitor. — see G-UX.
- **States:** [Existing CR](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S01-X--cr) · [Existing National ID (with future add-certificate branch)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S01-X--freelancer)

### S02 — Mobile OTP verification

- **Purpose:** Verify the applicant controls the mobile number.
- **Who sees it:** All applicants who passed the duplicate checks.
- **Entry condition:** S01 submitted, identity not already registered, OTP sent.
- **Required inputs:** 6-digit SMS code
- **Primary action:** Verify
- **Next:** Revenue routing → S03 Category (self-onboarding) or O-C (CR sales lead).
- **Alternative paths:** Incorrect code → inline error with remaining attempts.; Expired code → request new code (no attempt consumed).; 3 incorrect attempts → S02-L.; Edit mobile number → S01.; Resend code (cooldown + max resends, configurable).
- **Backend behaviour:** Simulated SMS only — real code never shown in the customer UI.; Development simulator strip (prototype only) triggers success / failure / expiry.
- **Business rules:** Max 3 incorrect attempts.; Resend cooldown/limit and expiry are provisional (D-04).
- **UX/UI notes:** Masked mobile number in the heading copy.; Countdown for resend; clear expiry recovery. — see G-UX.
- **States:** [Code sent](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S02--default) · [Incorrect code (2 attempts remaining)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S02--incorrect) · [Expired code (no attempt consumed)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S02--expired) · [New code sent](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S02--resent)

### S02-L — Mobile verification locked

- **Who sees it:** Applicants who entered 3 incorrect codes.
- **Entry condition:** Third incorrect OTP.
- **Required inputs:** None
- **Primary action:** Start again
- **Next:** S01 with a new application (demo).
- **Alternative paths:** Contact support.
- **Backend behaviour:** Lockout duration / cool-off policy to be defined (D-04).
- **Business rules:** No further OTP attempts on this application.
- **UX/UI notes:** Neutral tone; do not imply fraud. — see G-UX.

### S03 — Business category

- **Purpose:** Screen eligibility using the Madfu category catalogue BEFORE any paid verification.
- **Who sees it:** Self-onboarding applicants (CR in range, all freelancers).
- **Entry condition:** OTP verified and revenue routing = self-onboarding.
- **Required inputs:** Category; Subcategory
- **Primary action:** Next
- **Next:** CR → S04 CR verification. Freelancer → S06 Nafath.
- **Alternative paths:** Restricted subcategory → O-C (lead, internal CATEGORY_RESTRICTED).; Pending-review subcategory → O-C (configurable, D-13).; Freelancer + CR-only subcategory → continue with internal flag.
- **Backend behaviour:** Category API returns category/subcategory IDs, eligibility, permitted applicant types, manual-review flag.; No CR lookup or Nafath call happens for restricted categories (cost avoidance).
- **Business rules:** Madfu taxonomy ≠ government CR activity list.; Freelancer selection is preliminary; reconciled against the certificate later.; Fixture catalogue — not the real restriction list.
- **UX/UI notes:** Never show eligibility classification to the applicant.; Searchable select recommended for the real catalogue size. — see G-UX.
- **States:** [No selection](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S03--empty) · [Category and subcategory selected](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S03--selected) · [Validation — nothing selected](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S03--errors)

### S04 — Business verification (CR lookup)

- **Purpose:** Retrieve CR data from the government source and show the result.
- **Who sees it:** Registered Business applicants after category screening.
- **Entry condition:** Category decision = continue.
- **Required inputs:** None (automatic lookup)
- **Primary action:** Continue
- **Next:** S05 Authorized person selection.
- **Alternative paths:** Expired CR → notice, may continue (internal CR_EXPIRED).; Not found → Edit CR number → S01.; Unavailable → auto-retries, then "Try again" (bounded), then save-and-exit.; Provider error → generic error + retry.
- **Backend behaviour:** Bounded automatic retries (2) then manual retries (3) — provisional D-08.; Each call recorded in the cost ledger.; Never fabricate authorized-person data when the API fails.
- **Business rules:** Invalid / non-existent CR cannot proceed.
- **UX/UI notes:** Loading state with reassurance copy.; Recovery state must preserve progress. — see G-UX.
- **States:** [Loading — retrieving CR](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S04--loading) · [Valid CR](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S04--valid) · [Expired CR (may continue, flagged)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S04--expired) · [CR not found](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S04--not-found) · [Service unavailable after automatic retries](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S04--unavailable) · [Unexpected provider error](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S04--provider-error) · [Retry limit reached — progress saved](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S04--gave-up)

### S05 — Authorized person selection

- **Purpose:** Choose exactly one individual on the CR to verify with Nafath.
- **Who sees it:** Registered Business applicants with CR data.
- **Entry condition:** S04 result valid or expired.
- **Required inputs:** Single selection of one individual
- **Primary action:** Continue (disabled until a selection is made)
- **Next:** S06 Nafath verification.
- **Alternative paths:** No eligible individual → continue to S08 via manual-review path (contract disabled).; Related-party data unavailable → retry.; Back → S04.
- **Backend behaviour:** Companies and other entities are filtered out — individuals only.; Selected person’s National ID initiates Nafath.
- **Business rules:** Single-select only.; Name: first + last visible, 2nd/3rd masked. ID: first 3 + last 3 visible.; Changing the person never resets the Nafath attempt counter.
- **UX/UI notes:** Show role (owner / manager / partner).; One-person list is pre-selected but still confirmed by the user. — see G-UX.
- **States:** [Multiple individuals — none selected](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S05--multiple) · [One individual selected](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S05--selected) · [Single individual (pre-selected)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S05--one) · [No eligible individual (entities only)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S05--none) · [Related-party data unavailable](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S05--unavailable) · [Changing person after a failed attempt (counter preserved)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S05--after-failure)

### S06 — Nafath identity verification

- **Purpose:** Verify identity via a Nafath request with a two-digit matching number.
- **Who sees it:** CR: the selected authorized person. Freelancer: the National ID holder from S01.
- **Entry condition:** CR: person selected (S05). Freelancer: category decision = continue.
- **Required inputs:** None in Madfu — the user approves in the Nafath app
- **Primary action:** Send verification request → (wait) → Continue
- **Next:** Verified: CR → S08; Freelancer → S07 certificate selection.
- **Alternative paths:** 1st failure: Try again, or (CR) choose another person.; 2nd failure: CR → S08 manual path; Freelancer → S07-M manual certificate.; Technical failure: retry without consuming an attempt (provisional D-11).
- **Backend behaviour:** Max 2 attempts per application — shared across individuals.; Outcomes: verified, rejected, timed out, technical failure.; Each request recorded in the cost ledger.
- **Business rules:** Unverified Nafath → contract signing disabled.
- **UX/UI notes:** Very large circular number; numbered instructions.; Show remaining attempts after a failure.; Waiting state must survive refresh. — see G-UX.
- **States:** [Ready to send (CR, selected person)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S06--cr-ready) · [Waiting — large matching number](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S06--waiting) · [Rejected — 1 attempt remaining (CR)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S06--rejected) · [Timed out — 1 attempt remaining (Freelancer)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S06--timeout) · [Technical failure — no attempt consumed](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S06--technical) · [Verified](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S06--verified) · [Two unsuccessful attempts — manual path](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S06--exhausted) · [Waiting — Freelancer (National ID from entry)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S06--fl-waiting) · [Ready to send (Freelancer, National ID from entry)](https://wearemishkat.github.io/madfu-onboarding-wireframes/#/gallery/S06--fl-ready)

### S07-M — Manual certificate entry

- **Purpose:** Collect a certificate number when it cannot be retrieved after verification.

### S08 — Business details (shared)

- **Purpose:** Collect settlement IBAN, VAT, sales channels and branches.
- **Who sees it:** All self-onboarding applicants who reached this step (verified or manual path).

- **Business rules:** Max 2 unsuccessful ownership attempts per application.; IBAN failure never blocks the contract when Nafath succeeded.
- **UX/UI notes:** Inline status chip: Verifying / Verified / Not verified / Technical error.; Values preserved across navigation, retries and refresh. — see G-UX.

## Design decisions

- Desktop-first (1440 px), black/white low fidelity; single-column form (max 760 px) under a 7-step progress indicator that adapts to applicant type.
- Back is bottom-left (secondary), primary action bottom-right. Browser Back follows the same permitted transition; other URL changes snap back to the current step.
- Inline field errors plus an error summary when two or more fields fail; error emphasis by weight/border, not colour.
- Internal classifications are never shown; verification messages use neutral language.
- Nafath: dedicated screen, 192 px circular two-digit number, numbered instructions, remaining attempts after failures.
- Development simulator strips are hatched and labelled “prototype only”.
- Masking: names (first + last visible), National IDs (first 3 + last 3), mobile (last 3).
